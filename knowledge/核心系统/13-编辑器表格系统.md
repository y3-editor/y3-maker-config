# Y3 编辑器表格系统

> 编辑器内置的**表格管理系统**：策划可在地图中直接编辑一维/多维表格，逻辑侧通过 Lua API 读取。
> 本文档基于**编辑器源码**验证（`E:\map\src\Server\server\engine\dm\editor\`：`helper/table_helper.py`、`view/main_window_new/table_editor/`）。

---

## 一、概念

| 表类型 | 常量 | 命名前缀 | 用途 |
|--------|------|----------|------|
| 多维表（数据表） | `TableType.TypeConfig = 0` | `config` | 行 × 列，支持多级主键，逻辑侧按 key 链取值 |
| 一维表（全局表/KV 表） | `TableType.TypeKV = 1` | `kv` | key → value 扁平映射 |

- 新建表自动编号：`config1`、`config2`… / `kv1`、`kv2`…（`table_editor_manager.get_next_table_name`）
- 表名合法字符：不含 `\ / ? * [ ]`，不允许重名

## 二、文件位置

| 位置 | 路径 | 说明 |
|------|------|------|
| 地图表 | `maps/<map>/tables/*.json` | 每表一个 JSON（`TableManager.TABLE_DATA_FOLDER='tables'`） |
| 项目表 | `archive/init_tables/` | 项目级表（`TableManager.PROJ_TABLE_FOLDER`），随存档初始化 |
| 分组索引 | `maps/<map>/editor/tableeditorgroupinfo.json` | 表名 ↔ uuid 映射，编辑器面板树 |

> 表扫描目录 = `tables/` + `archive/init_tables/` 两个目录，支持 `.json/.xlsx/.xlsm/.xls/.csv`（`SUPPORT_FILE_TYPES` 注册）。

## 三、JSON 落盘格式

JSON 为编辑器 `serialize()` 直出，0-based 行索引。

### 3.1 多维表（`table_type: 0`）

```json
{
    "column_width": {},
    "table_data": {
        "column_desc": {},          // {列索引: 列描述}
        "data": [
            ["key", "hp", "attack"],    // data[0] 列名行
            ["int", "int", "int"],      // data[1] 类型行
            ["boss", "10000", "200"]    // data[2..] 数据行
        ],
        "key": [0]                  // 主键列索引数组（最多 3 列）
    },
    "table_type": 0,
    "tid": "244cee57-..."
}
```

- **`data[0]` 列名行、`data[1]` 类型行、`data[2..]` 数据行**
- `key` 数组 = 主键列索引，加载时映射为 `key1`/`key2`/`key3`（`_restore_table_data`）
- 新建表默认：50 数据行 + 5 头行 = **55 行 × 20 列**（`DEFAULT_ROW_COUNT=50`、`DEFAULT_COLUMN_COUNT=20`）
- 默认主键：第 0 列，列名 `key`，类型 `int`

### 3.2 一维表（`table_type: 1`）

```json
{
    "column_width": {},
    "table_data": {
        "data": [
            ["Key", "Type", "Value", "Des"],  // data[0] 表头行（固定 4 列）
            ["boss_hp", "int", "10000", "Boss生命"],  // data[1..] 数据行
            [null, null, null, null]
        ],
        "key": [0],
        "kv_key_type": "str"        // 仅 "int" / "str"
    },
    "table_type": 1,
    "tid": "89b305c5-..."
}
```

- 固定 4 列：`Key / Type / Value / Des`（`KV_HEADERS`、`KV_COLUMN_COUNT=4`）
- `kv_key_type` 仅 `int`/`str`，其他值回退 `str`；导出时决定 key 是否转 int

### 3.3 分组索引

```json
[
    {"__tuple__": true, "items": ["244cee57-...", "config1"]},
    {"__tuple__": true, "items": ["89b305c5-...", "kv1"]}
]
```

`[uuid, 表名]`，与表文件内 `tid` 一致。

## 四、单元格类型与默认值

导出时按类型行声明的类型转换（`TYPE_CONVERTER`），空值补默认值（`DEFAULT_VALUES`）：

| 类型 | 转换规则 | 默认值 |
|------|----------|--------|
| `string` | 转 str | `""` |
| `int` | int（范围 ±9.2e18） | `0` |
| `float` | float | `0.0` |
| `bool` | `true`/`1` → true | `false` |
| `angle` | float | `0.0` |
| `vector3` | 解析 `(x,y,z)`（兼容全角括号） | `(0.0, 0.0, 0.0)` |

## 五、主键规则

- 最多 **3 级主键**：`key1` / `key2` / `key3`（对应运行时 `get_table_var` 的 key1..key5 参数）
- 主键列类型**仅限 int/string**，否则导出报错
- key 标识不能重复、不能跳级（有 key3 必有 key1/key2）
- **无主键列时自动生成虚拟主键** `__auto_gen_key`（int 类型，值为行号）
- 主键为空的行导出时跳过
- KV 表主键类型通过 `kv_key_type` 切换（编辑器目录树右键「切换主键类型」）

## 六、校验规则（编辑期）

| 错误 | 含义 |
|------|------|
| key_missing / key_error / key_repeat | 主键缺失 / 含空格 / 重复 |
| name_missing / name_error / name_repeat | 属性名缺失 / 含空格 / 重复 |
| value_type_error / value_error | 类型非内置 / 值与类型不匹配 |
| kv_key_type_error | KV 主键类型非 int（提示去目录树切换） |
| kv_value_type_missing | KV 行有 key 无类型 |

## 七、运行时读取（lualib）

### 7.1 导出为 Lua 的数据结构

编辑器导出表 → Lua 字符串（float 转 `Fix32`）：

- **多维表** → 嵌套表：`{key1: {key2: {key3: {列名: 值, ...}}}, ...}`
- **KV 表** → 扁平表：`{key: value, ...}`

### 7.2 API

```lua
local t = y3.game.get_table("kv1", true)      -- as_lua=true：Fix32 转 number
local v = GameAPI.get_table_var(t, "boss", "hp", 0)  -- 多级 key + 默认值
local n = GameAPI.get_table_length(t)
```

| API | 说明 |
|-----|------|
| `y3.game.get_table(name, as_lua)` | 按表名取表（推荐） |
| `GameAPI.get_table_var(t, key1..key5, default, convert)` | 取单元格值 |
| `GameAPI.set_table_value(t, value, key1..key5, convert)` | 写值（仅内存，编辑器保存才落盘） |
| `GameAPI.get_table_length` / `is_table_empty` / `table_has_key` | 元信息 |
| `GameAPI.remove_table_value` / `insert_table_value` | 删/插 |
| `GameAPI.get_new_table` / `clear_table` / `get_copy_of_table` / `dump_table` | 运行时表操作 |

## 八、工具链

`table_reader.py`（`.codemaker/skills/eca-json-builder/`）可读 JSON 表：

```bash
py -3 table_reader.py list maps/EntryMap/tables/
py -3 table_reader.py read maps/EntryMap/tables/kv1.json --key boss_hp
```

> ⚠️ `table_reader.py` 将 `data[0]` 当表头：KV 表正确；**多维表会把类型行（data[1]）当数据行**，读多维表需自行偏移。

## 九、注意事项

1. **优先在编辑器「表格」面板编辑**：JSON 为编辑器直出格式，手改需保持 tuple 结构与 0-based 布局
2. **表名即文件名 + 运行时表名**：编辑器新建 `kv1` → 文件 `tables/kv1.json` → 运行时 `y3.game.get_table("kv1")`
3. **运行期写表不落盘**：`set_table_value` 只改内存
4. **外部表可导入**：把 `.xlsx/.csv` 放入 `tables/` 或 `archive/init_tables/`，按 sheet 名 `config_*`/`kv_*` 前缀判定类型（JSON 表按 `table_type` 字段）
5. **项目表与存档**：`archive/init_tables` 的表随存档初始化，导出时经 `ArchiveType.get_proj_table_real_name` 改名
6. **与 KV 系统区别**：本系统是独立表格文件；物编 KV（etype 61）存于物编 JSON 内，二者数据源不同
