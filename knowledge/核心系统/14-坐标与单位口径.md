# 坐标与单位口径（米 / 厘米 / 格子）

> 运行时实测整理。**这是最容易造成"数值填对了但表现离谱"或"命令没效果"的地方**，
> 做地形、摆逻辑节点、写触发器、做单位命令之前先看这一页。

## 1. 四套口径对照表

| 场景 | 单位 | 参考值 |
|------|------|--------|
| **逻辑资源**（`logicres.json` 里的点 / 区域） | **米** | 例：`(-36, 0)` |
| 编辑器面板 / 镜头焦点（`y3.camera.get_attr_integer('focus_x')`） | **米** | 例：跟随单位时读到 `-36` |
| MCP `add_point(pos_x, pos_y)` / `add_rect_area(...)` 的**入参** | **厘米** | 传 `-3600` → 存成 `-36` |
| 运行时 Lua `y3.point.create(x, y)` / `unit:get_point()` | **厘米** | 出生点读到 `{Point|-3600, 0, 0}` |
| 单位物编的长度字段（`attack_range` / `ori_speed` / `sight_range` / `alarm_range`） | **米** | 官方远程单位模板默认 `attack_range = 5.25` |
| 物编技能的范围字段（`circle_radius` / `sector_radius`） | **米** | 例：`circle_radius = 4.0` 即半径 4 米 |
| ECA 形状半径（`CONST_CIRCULAR_SHAPE` / 扇形 / 环形 / 矩形形状的构造入参） | **厘米** | 同一个技能写 `CONST_CIRCULAR_SHAPE(400)` 才等于物编的 4 米 |
| 玩家属性 / 奖励数值等无量纲字段 | 数值 | — |

**换算**：`厘米 = 米 × 100`。

> ⚠️ 策划案常以厘米写射程（`128 / 500 / 600`），落到物编要 **÷100**（`1.28 / 5.0 / 6.0`）；
> 直接填 `600` 会得到 600 米射程（整张图）。
>
> ⚠️ **反过来**：策划案里的「6.5 米范围」写进 ECA 技能触发器要 **×100** → `CONST_CIRCULAR_SHAPE(650)`。
> 照抄 `6.5` 只会打到贴脸的单位（实测：半径 1 命中 1 只、500 命中 6 只、2000 仍是 6 只，
> 单位是厘米坐实）。

## 2. 地图尺寸

运行时实测：`GameAPI.get_usable_map_range()` → `RectangleAreaRes<-64, -64, 128, 128>`

```
世界坐标 = [-64, 64] × [-64, 64]（米）   即 128 m × 128 m，原点在地图正中
厘米口径 = [-6400, 6400] × [-6400, 6400]
```

> ⚠️ `knowledge/核心系统/09-地形系统.md` 里写的「左下角原点 / 地形格子 50×50cm」
> 与实际运行时**不一致**，点位摆放请以本节为准（用 `get_usable_map_range()` 现测最保险）。

## 3. 常见误用与后果

| 误用 | 后果 |
|------|------|
| 把厘米值填进物编长度字段 | 射程 / 视野放大 100 倍（隔着整张图打人） |
| 把米值填进 ECA 形状半径（`CONST_CIRCULAR_SHAPE(6.5)`） | 范围缩成 6.5 厘米，等于只打自己脚下，表现为「技能没效果」 |
| 物编 `circle_radius`(米) 与 ECA `CONST_CIRCULAR_SHAPE`(厘米) 两边不一致 | 指示器画 4 米、实际打到 40 米（或反过来），玩家会觉得「技能判定不对」 |
| 把米值传给 `y3.point.create` | 点位挤在地图中心 1 米内（看起来"全部叠在一起"） |
| 拿 `point.create` 的返回值跟 `logicres.json` 里的值直接比 | 差 100 倍，会误判"坐标不对"、"命令无效" |
| 相机/镜头偏移量单位混用 | 镜头贴脸或飞到天外 |

## 4. 取证姿势（避免把人坑进去）

```lua
-- 逻辑资源（米）与运行时点位（厘米）并排看，一眼看出口径
local pt  = y3.point.get_point_by_res_id(10003)      -- 米
local u   = y3.player.get_by_id(1):get_all_units():get_first()
print(tostring(pt), tostring(u:get_point()))          -- 米 vs 厘米

-- 镜头焦点（米）
print(y3.camera.get_attr_integer('focus_x'), y3.camera.get_attr_integer('focus_y'))
```

### ⚠️ 取证时另一个坑：同帧创建多只单位会被引擎挪位

同一帧里连续创建多只单位，返回的坐标会被引擎重新分配到网格点
（甚至落到图外），据此得出的结论**全是错的**。

> **做坐标 / 位置取证时，一帧只创建一只单位**，或用间隔定时器分批创建。

## 5. 角度口径：引擎一律用**角度制**

与长度不同，**角度没有第二套口径** —— 引擎与 Lua 库统一使用**角度制（度）**：

| 场景 | 口径 |
|------|------|
| `y3.math.sin / cos / tan` | **角度制**（`y3/game/math.lua` 顶部注释：「均使用角度制」，内部才乘 `math.rad`） |
| 单位朝向 `unit:get_facing() / set_facing()` | 角度制 |
| `ability:get_angle()`（施法方向） | 角度制 |
| ECA 取值函数 `GET_ABILITY_RELEASE_DIRECTION(技能)` | 角度制 |
| ECA 的 `ANGLE` 参数（如 `CONST_SECTOR_SHAPE_NEW(半径, 张角, 方向)` 的第 3 参） | 角度制 |
| `y3.particle.create{ angle = ... }` | 角度制 |

> ⚠️ 凡是要自己算 `sin/cos` 或把方向填进 ECA 形状参数时，**直接用角度，不要 `math.rad`**；
> 只有直接调用 Lua 标准库 `math.sin` 才需要自己转弧度（这也是 `y3.math` 存在的意义）。
