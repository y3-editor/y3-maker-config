## 0. 基准使用规则

### 0.1 每轮必须固定

| 项 | 要求 |
|----|------|
| 基准文件 | 使用本文件，运行前记录 SHA256；中途不改 |
| 起始工程 | 从同一个干净快照开始；每轮结束恢复到该快照 |
| 模型与参数 | 同一模型、同一推理强度、同一时间预算 |
| 工具权限 | 同一套 MCP / skill 权限，不额外开小灶 |
| 重复次数 | 同一配置至少 3 轮，报告分数分布，不报单轮最好成绩 |

> **干净快照的定义**：只保留引擎、地形模板、官方 UI 和工程基础配置；
> 不包含上一轮生成的自定义物编、触发器、业务全局变量和自制画板。
> 如果没有这样的快照，先在基准运行前生成一份，并记录它的哈希。

### 0.2 被测 AI 可以看什么

- 本基准文件。
- 工程里的引擎文档、`knowledge/`、`memory/`、当前 skills。
- 当前工程的真实状态文件（例如逻辑节点、物编、UI 清单）。

### 0.3 被测 AI 不能看什么

- 答案版执行案（不随题下发）。
- 历史测试报告、历史修改记录、上一轮的触发器 / 物编答案。
- 评分表里的 Q1~Q10 参考结论（不随题下发）。

> 如果被测 AI 读到了答案版，本轮作废，不纳入 skills 迭代对比。

### 0.4 判定原则

- 只认**可观察证据**：游戏内现象、回读的工程文件、探针日志、测试报告。
- 不认“静态校验全绿”“参数都填了”“应该会生效”。
- 任何“引擎会自动做”的判断，必须用最小实验证明；不能只查文档或凭经验。

## 1. 任务目标

在 Y3 编辑器中从零制作一张单人经典塔防地图：

- 玩家保护终点基地，怪物从固定路径起点刷新并沿 14 个航点走向基地。
- 初始金币 200、基地生命 10；漏怪扣基地生命，归零即失败。
- 可建造 4 种防御塔，支持升级到 Lv3 与出售。
- 共 10 波，第 10 波包含 Boss；全部清空后胜利。
- 建造使用引擎自带建造技能与建造指示器，不自制塔选择面板。
- 全流程纯 ECA：**不产出任何 `.lua` 文件**。

## 2. 硬约束

| 约束 | 说明 |
|------|------|
| 纯 ECA | 全局触发器、物编触发器、ECA 函数、ECA 变量；禁止 Lua |
| 物编走脚本 / 工具 | 单位、技能、魔法效果、物品不得手写工程 JSON |
| UI 走 UI 流程 | 画板、控件、事件绑定按当前 UI 工具链生成 |
| 触发器走 ECA 流程 | 生成、加载、回读、对账按当前 ECA 工具链执行 |
| 地形用模板 | 必须使用 `easy-tower-defense-terrain` 地形模板（含 14 航点路径）；不得自行重绘地形、增删装饰物或改航点 |
| 建造用引擎 | 使用真·建造技能（`ability_cast_type=4`）提供的指示器与碰撞校验；不自制建造区域或塔选择面板 |
| 热更后保存 | 物编 / UI 改动必须热更，等待后再保存 |
| 串行导入 | UI 与触发器导入不得并发 |
| 失败熔断 | MCP 超时不重试；连续失败 2 次停止并出报告 |
| 不改引擎 | 不使用自定义 Python / 引擎源码改动绕过问题 |

## 3. 功能规格

### 3.1 地形与路径

| 项 | 要求 |
|----|------|
| 地形模板 | `easy-tower-defense-terrain`，保留模板原始尺寸，不改 `resize_terrain` |
| 路径 | 固定单路线，14 个航点，单向行进 |
| 刷怪点 | 路径首个航点 |
| 基地位置 | 路径末个航点 |
| 到达判定 | 怪物进入基地判定范围即视为漏怪，扣基地生命并移除该怪物 |
| 漏怪扣血 | 普通怪 / 精英怪 / 飞行怪各 -1；Boss -5 |

要求：

- 路径与刷怪点坐标取自当前工程实际节点，不写死模板以外的坐标。
- 逻辑节点必须语义化命名；基准不提供固定 `res_id`。
- 地形只作视觉层，不产生战斗增益或减益。

### 3.2 防御塔（4 种）

| 塔 | 建造费用 | HP | 攻击 | 攻击间隔 | 射程 | 特性 |
|----|---------|----|------|---------|------|------|
| 箭塔 | 50 | 1000 | 50 | 0.8s | 600 | 单体，攻速快 |
| 魔法塔 | 80 | 1000 | 100 | 1.5s | 800 | 单体，射程远 |
| 炮塔 | 100 | 1000 | 80 | 2.0s | 500 | 命中点 200 半径 AOE |
| 冰塔 | 70 | 1000 | 30 | 1.0s | 600 | 命中后减速 50%，持续 2s |

要求：

- 塔归属玩家 1，建造后不可移动。
- 自动攻击射程内最近的敌方单位；目标离开射程后重新选取。
- 4 种塔都必须有可见的弹道或攻击表现。
- 塔的可建造位置由引擎建造指示器与碰撞校验决定；路径上、已有单位处不可建造。

### 3.3 敌人（5 种）

| 敌人 | HP | 移动速度（世界单位/秒） | 护甲 | 击杀金币 | 出现波次 | 特性 |
|------|----|------------------------|------|---------|---------|------|
| 史莱姆 | 200 | 100 | 0 | 5 | 1~3 | 数量多 |
| 哥布林 | 150 | 175 | 0 | 8 | 2~5、8~9 | 高速 |
| 石头人 | 800 | 60 | 5 | 15 | 4~7、9~10 | 高血量、重甲 |
| 飞行怪 | 300 | 125 | 0 | 12 | 6~9 | 飞行，高度 200 |
| Boss | 3000 | 75 | 10 | 100 | 10 | 超高血量 |

要求：

- 敌人归属中立敌对玩家（31）。
- 刷新后沿路径单向行进，不回头、不内耗。
- 飞行怪只能被箭塔、魔法塔、冰塔攻击；炮塔不得对其造成伤害。
- 移动速度以“同一段路径的实际通过时间”验收，不看面板字段。

### 3.4 基地与建造技能

| 项 | 要求 |
|----|------|
| 基地 | 建筑，不可移动，玩家 1 所有，初始生命 10 |
| 建造技能 | 每个塔 1 个独立建造技能，共 4 个，挂在基地技能列表上 |
| 建造交互 | 基地默认选中，引擎自动展示 4 个建造按钮；点击后进入建造指示器，确认位置完成建造 |
| 金币不足 | 建造完成时扣费失败，必须撤销该塔并给出提示，不能留下免费塔 |
| 选中锁定 | 基地常驻选中，禁用点选 / 框选；仍需能点击已建塔打开升级面板 |

要求：

- 基地生命必须以可观察方式维护，并反映到 HUD；不要求使用引擎原生 HP。
- 4 个建造技能都要在基地技能栏可见、可点击、可完成建造。
- 建造技能不依赖自定义 UI 面板。

### 3.5 波次与刷怪

| 项 | 要求 |
|----|------|
| 波数 | 10 波 |
| 开局等待 | 游戏开始后 5 秒刷第 1 波 |
| 波次间隔 | 12 秒 |
| 单波刷怪间隔 | 1.2 秒 |
| 组成 | 按下表；同一波内按顺序刷新 |

| 波次 | 怪物组成（数量） |
|------|------------------|
| 1 | 史莱姆 ×3 |
| 2 | 史莱姆 ×3 + 哥布林 ×1 |
| 3 | 史莱姆 ×3 + 哥布林 ×2 |
| 4 | 哥布林 ×2 + 石头人 ×1 |
| 5 | 哥布林 ×3 + 石头人 ×2 |
| 6 | 石头人 ×2 + 飞行怪 ×2 |
| 7 | 石头人 ×2 + 飞行怪 ×2 |
| 8 | 飞行怪 ×3 + 哥布林 ×3 |
| 9 | 石头人 ×2 + 飞行怪 ×2 + 哥布林 ×2 |
| 10 | Boss ×1 + 石头人 ×2 |

要求：

- 波次必须按时间自动推进，不依赖玩家操作。
- 每波开始与结束都要有可观察提示（HUD 文本或中央提示）。
- 第 10 波必须包含且只包含 1 只 Boss。

### 3.6 战斗规则

| 规则 | 要求 |
|------|------|
| 目标选择 | 射程内最近敌人；同距离时任选其一，但不得随机跳目标导致空转 |
| AOE | 炮塔命中后对命中点 200 半径内所有敌人造成伤害；不得因 AOE 再次触发自身而递归 |
| 减速 | 冰塔命中后目标移动速度 -50%，持续 2 秒；重复命中只刷新持续时间，不叠加 |
| 飞行 | 炮塔不能攻击飞行怪；其余 3 种塔可以 |
| 死亡 | 敌人死亡后立即移除，并按类型发放金币 |
| 伤害来源 | 塔造成的伤害必须有可回读的数值变化（血量下降），不能只播特效 |

### 3.7 经济与成长

| 项 | 要求 |
|----|------|
| 初始金币 | 200 |
| 击杀金币 | 按 §3.3 表 |
| 升级 | 每座塔可升到 Lv3；Lv2 / Lv3 的攻击力按 Lv1 基础值累加提升 |
| 出售 | 返还该塔已投入金币（建造 + 已支付升级）的 50%，向下取整 |
| 金币显示 | HUD 实时显示，建造 / 升级 / 出售 / 击杀后立即变化 |

| 塔 | Lv1→Lv2 | Lv2→Lv3 | 每级攻击提升 |
|----|---------|---------|-------------|
| 箭塔 | 30 | 50 | +20% |
| 魔法塔 | 50 | 80 | +25% |
| 炮塔 | 60 | 100 | +20% |
| 冰塔 | 40 | 70 | +15% |

> 例：箭塔 Lv2 攻击 = 50 × 1.2 = 60；Lv3 攻击 = 50 × 1.4 = 70。

### 3.8 胜负、结算与重开

| 项 | 要求 |
|----|------|
| 失败 | 基地生命降到 0 及以下 |
| 胜利 | 第 10 波全部敌人死亡（含 Boss） |
| 结算 | 显示胜负、到达波次、击杀数、剩余金币、剩余生命、用时 |
| 重新开始 | 清空塔与敌人、复位金币 200 / 生命 10 / 波次 1，重新开始倒计时 |
| 退出 | 二次确认后退出游戏 |

要求：

- 胜利只能结算一次；失败与胜利不得同时触发。
- 最后一波清空后必须等待所有已刷出的敌人死亡再判胜，不能以“最后一波已开始”判胜。
- 重新开始必须注销上一局的计时器；不得出现上一局继续刷怪。
- 重开后 HUD、金币、生命、波次必须立即回到初始值。

### 3.9 界面

| 界面 | 必须包含 |
|------|----------|
| 波次信息栏 | 波次、金币、基地生命、击杀数、退出按钮、波次提示 |
| 塔升级面板 | 塔名、等级、升级费用、升级 / 出售 / 取消按钮 |
| 结算界面 | 胜负标题、到达波次、击杀、金币、剩余生命、用时、重新开始 / 退出 |
| 退出确认 | 提示文字、确认 / 取消按钮 |

要求：

- 4 个界面都能显示 / 隐藏，切换后不残留上一界面的遮挡。
- 波次信息栏必须随金币、生命、波次、击杀实时刷新；不能停在初始值。
- 塔升级面板必须显示当前选中塔的真实等级与费用。
- 点击事件必须真正驱动 ECA；不能用“事件已注册”代替“点击有反应”。
- 引擎自带建造按钮不属于自定义 UI，不要重做塔选择面板。

### 3.9.2 项目自带 GameHUD 处理（强制）

工程自带的官方 `GameHUD`（约 2.7 MB / 约 1000 节点）会占据屏幕底部和右侧，直接盖住自定义 HUD。执行时必须显式隐藏它，而不是删除文件：

1. 生成/调整自定义 HUD 后，打开 `maps/<地图>/ui/GameHUD.json`，把**根节点** `visible` 置为 `false`（或在 UI 编辑器里隐藏该画板）。
2. 保留 `GameHUD.json` 文件本身，不要删除、不要改名、不要用自建画板覆盖同名文件。
3. 隐藏后执行 `hotfix_ui_editor` → 等待 3 秒 → `save_editor`。
4. 回读确认 `GameHUD.json` 根节点 `visible = false`，并用对局截图确认官方 HUD 不再出现。
5. 若后续需要恢复官方 HUD，把根节点 `visible` 改回 `true`，再走一次热更与保存。

> 官方 `LoadingPanel` / `LogoPanel` / `loss` / `win` 可以保留；本条只要求隐藏常驻的 `GameHUD`。

### 3.9.3 UI 验收口径（强制）

只截图“看起来差不多”不算通过，必须同时满足：

1. `check_layout.py` 对本项目 4 个画板的检查结果为 0 越界、0 安全区外。
2. 按 §3.9.1 表格逐项回读控件坐标，偏差必须为 0；不允许“目测居中”。
3. 4 个画板逐个显隐，切换后无上一界面的残留遮挡。
4. 波次信息栏显示的金币 / 生命 / 波次 / 击杀与真实状态一致，并在数值变化后立即刷新。

8. 重生成画板时已有控件 uid 保持稳定；新增/删除控件后重新解析 uid 并重导引用它的触发器，`audit_triggers.py` 无“引用了不存在的控件 uid”。

### 3.10 场景与逻辑节点

- 地形使用 `easy-tower-defense-terrain` 模板，不自行改地形、装饰物与资源摆件。
- 逻辑节点：路径 1 条（14 航点）；刷怪点与基地点取路径首末航点，无需额外点节点。
- 逻辑节点必须语义化命名。
- `res_id` 以当前工程 `logicres.json` 为准；基准不提供固定编号。

## 6. 验收标准

### 6.1 功能验收

- 基地默认选中，4 个建造按钮可见；4 种塔都能在合法位置建成。

- 每个“引擎自动完成”的判断都有实验证据。
