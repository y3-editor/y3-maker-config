> **用途：固定基准题。** 用于反复测试 AI 在 Y3 编辑器中编写纯 ECA 项目的能力，并比较 skills 迭代前后的效果。
>
> **这不是答案版。** 本文件不提供上一轮的实现结论、真实 Key、res_id、触发器数量或踩坑答案。
> 这些内容在答案版执行案中（不随题下发），**被测 AI 不得读取**。
>
> 基准版本：`v1.1`
> 冻结日期：2026-10-20
> 起始工程：干净快照（无上一轮触发器、无上一轮物编残留）
> 评分规则：由评分者单独持有，不随题下发。

## 0. 基准使用规则

### 0.1 每轮必须固定

| 项 | 要求 |
|----|------|
| 基准文件 | 使用本文件，运行前记录 SHA256；中途不改 |
| 起始工程 | 从同一个干净快照开始；每轮结束恢复到该快照 |
| 模型与参数 | 同一模型、同一推理强度、同一时间预算 |
| 工具权限 | 同一套 MCP / skill 权限，不额外开小灶 |
| 重复次数 | 同一配置至少 3 轮，报告分数分布，不报单轮最好成绩 |

> **干净快照的定义**：只保留引擎、地形模板、官方 UI 和工程基础配置；
> 不包含上一轮生成的自定义物编、触发器、业务全局变量和自制画板。
> 如果没有这样的快照，先在基准运行前生成一份，并记录它的哈希。

### 0.2 被测 AI 可以看什么

- 本基准文件。
- 工程里的引擎文档、`knowledge/`、`memory/`、当前 skills。
- 当前工程的真实状态文件（例如逻辑节点、物编、UI 清单）。

### 0.3 被测 AI 不能看什么

- 答案版执行案（不随题下发）。
- 历史测试报告、历史修改记录、上一轮的触发器 / 物编答案。
- 评分表里的 Q1~Q10 参考结论（不随题下发）。

> 如果被测 AI 读到了答案版，本轮作废，不纳入 skills 迭代对比。

### 0.4 判定原则

- 只认**可观察证据**：游戏内现象、回读的工程文件、探针日志、测试报告。
- 不认“静态校验全绿”“参数都填了”“应该会生效”。
- 任何“引擎会自动做”的判断，必须用最小实验证明；不能只查文档或凭经验。

## 1. 任务目标

在 Y3 编辑器中从零制作一张单人生存地图：

- 玩家进入后选择 1 个英雄。
- 英雄在中心基地防守，怪物从四角刷新并主动进攻。
- 共 10 波，击杀怪物获得金币与经验，概率掉落装备。
- 英雄死亡后自动复活，复活次数耗尽后失败。
- 第 10 波清空后胜利。
- 全流程纯 ECA：**不产出任何 `.lua` 文件**。

---

## 2. 硬约束

| 约束 | 说明 |
|------|------|
| 纯 ECA | 全局触发器、物编触发器、ECA 函数、ECA 变量；禁止 Lua |
| 物编走脚本 / 工具 | 单位、技能、魔法效果、物品不得手写工程 JSON |
| UI 走 UI 流程 | 画板、控件、事件绑定按当前 UI 工具链生成 |
| 触发器走 ECA 流程 | 生成、加载、回读、对账按当前 ECA 工具链执行 |
| 热更后保存 | 物编 / UI 改动必须热更，等待后再保存 |
| 串行导入 | UI 与触发器导入不得并发 |
| 失败熔断 | MCP 超时不重试；连续失败 2 次停止并出报告 |
| 不改引擎 | 不使用自定义 Python / 引擎源码改动绕过问题 |

### 3.8.1 UI 布局目标（强制）

#### A. 全局坐标与安全区

| 项 | 要求 |
|----|------|
| 设计分辨率 | `1920 × 1080` |
| 坐标口径 | 下表统一使用 **HTML 预览坐标（左上原点，Y 向下）**；`html_to_y3_ui.py` 会转换为 Y3 左下原点 |
| 左右安全区 | 所有**常驻**控件必须落在 `x = 100 ~ 1820`。非 16:9 窗口会裁掉左右各约 100px，越界即视为 UI 失败 |
| 上下留白 | 常驻控件建议 `y = 32 ~ 1048`；底部技能栏与装备栏底边统一 `y = 1048` |
| 外边距 | 左右 `100px`，上下 `32px`。不要为了“贴边”把常驻控件放到 `x < 100` 或 `x + w > 1820` |
| 常驻画板底图 | `BattleHUD`、`ItemBar` 必须删除根 layout 的 `<画板名>_bg`，否则会出现全屏半透明遮罩 |
| 全屏画板底图 | `HeroSelect`、`ResultPanel`、`ExitConfirm` 保留全屏底板，用于盖住地图 |

> 这套坐标是**验收基准**，不是参考建议。每轮执行必须按表落地；截图或回读坐标与表不一致即视为布局偏差。

### 3.8.2 项目自带 GameHUD 处理（强制）

工程自带的官方 `GameHUD`（约 2.7 MB / 约 1000 节点）会占据屏幕底部和右侧，直接盖住自定义 HUD。执行时必须显式隐藏它，而不是删除文件：

1. 生成/调整自定义 HUD 后，打开 `maps/<地图>/ui/GameHUD.json`，把**根节点** `visible` 置为 `false`（或在 UI 编辑器里隐藏该画板）。
2. 保留 `GameHUD.json` 文件本身，不要删除、不要改名、不要用自建画板覆盖同名文件。
3. 隐藏后执行 `hotfix_ui_editor` → 等待 3 秒 → `save_editor`。
4. 回读确认 `GameHUD.json` 根节点 `visible = false`，并用对局截图确认官方 HUD 不再出现。
5. 若后续需要恢复官方 HUD，把根节点 `visible` 改回 `true`，再走一次热更与保存。

> 官方 `LoadingPanel` / `LogoPanel` / `loss` / `win` 可以保留；本条只要求隐藏常驻的 `GameHUD`。

### 3.8.3 UI 验收口径（强制）

只截图“看起来差不多”不算通过，必须同时满足：

1. `check_layout.py` 对本项目 5 个画板的检查结果为 0 越界、0 安全区外。
2. 按 §3.8.1 表格逐项回读控件坐标，偏差必须为 0；不允许“目测居中”。
3. 5 个画板逐个显隐，切换后无上一界面的残留遮挡。
4. 血条/蓝条显示 `当前 / 最大`，并随英雄受伤、升级、装备变化刷新。
5. 技能格显示对应英雄的 4 个技能图标与冷却；Q/W/E/R 快捷键生效。
6. 物品栏 4 格实际显示 BAR 第 1~4 格装备。
7. 退出、确认、取消、重开按钮点击后都有可观察结果，不以“事件已注册”代替点击验收。
8. `GameHUD.json` 根节点 `visible = false`，对局截图中没有官方 HUD。
9. 重生成画板时已有控件 uid 保持稳定；新增/删除控件后重新解析 uid 并重导引用它的触发器，`audit_triggers.py` 无“引用了不存在的控件 uid”。

## 6. 验收标准

- 能进入英雄选择，5 张卡都能选中并创建对应英雄。

- 无 `.lua` 文件。

- 每个“引擎自动完成”的判断都有实验证据。
